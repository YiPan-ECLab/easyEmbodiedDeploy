# 自定义工作流

把可复用关键点、夹爪、等待和多个 VLA 模型组合为一个执行流。关键点由工作流统一发送，模型进程只做推理；每次启动工作流时按实际反馈检查零位，必要时先双从臂平滑回零；流程内部切换步骤不回零。

## 打开模块

编排时拖动步骤左侧的 ⠿，其他卡片会在松手前让出插入空位；松手确认顺序，按 Esc 或拖到列表外取消。上下箭头也可调整顺序。

「运动与衔接参数 → 关节下发接口」可选 `move_js`（默认透传）或 `move_j`（固件规划），保存后随工作流复用。选择作用于关节关键点、关节型 VLA 和夹爪步骤保持的关节目标；仍按运控 Hz 下发软件插值目标，保留暂停、停止与衔接逻辑。末端目标仍用 `move_p`，平滑回零仍用 `move_j`。

`move_js` 已是 SDK 的快速响应接口，切换 `move_j` 不保证提速。关键点实际时长取期望时长与速度、加速度所需时长的较大值；希望更快时需同时检查这三项，单纯提高运控 Hz 不会缩短计划时长。VLA 取动作频率由模型的 policy Hz 控制。

工作台的「部署」分组包含「自定义工作流」。若工作台正在采集数据，保持原服务运行，单独启动本模块：

```bash
thirdParty/.venvs/piper-home/bin/python scripts/Workflow/web_server.py --host 127.0.0.1 --port 8094
```

打开 `http://127.0.0.1:8094`。页面可选择真实从臂或模拟器，启动服务及打开页面都不会连接硬件。真实设备连接复用采集、标定和部署的跨进程设备锁，采集正在占用设备时会直接拒绝连接，不停止采集。

## 推荐操作顺序

页面按「1 · 连接从臂 → 2 · 录制关键点 / 3 · VLA 模型 → 4 · 编排工作流 → 5 · 执行」组织。三个入口分别显示已有关键点、模型和步骤数量。只使用关键点时不需要配置模型、相机、HDF5 或运动参数。

1. 选择真实从臂或模拟器，点击「连接」。连接只读，不回零、不使能；实际硬件只使用 `piper-lo`、`piper-ro`，不连接主臂。
2. 选择要录制的从臂，**使用机械臂机身示教按钮进入可拖动模式**。网页「开始连续录点」只切换录点界面状态，不释放、不使能、不切换机械臂模式；也可直接点击录制。
3. 拖到目标并停稳，填写名称 → **录制当前点**。列表立即展示保存的 J1–J6 角度、夹爪毫米值，以及 CAN 接口和反馈时效。可以连续录多个点。
4. 录完用机身按钮退出示教。在点列表点击「添加步骤」，调整顺序并保存 → **执行工作流**。无需先点回零，也无需先结束网页录点。
5. 执行时若机身仍在示教模式，页面明确等待按钮退出；退出后自动继续。未在零位则先双从臂平滑回零，保留夹爪宽度，再执行步骤。模型可以同时在后台加载。

机身按钮退出后，固件可能仍显示控制模式为「示教」，同时示教状态已是「结束记录」。正常状态下，此组合允许回零或执行；无需反复按按钮。仍在录制时，网页会显示等待退出的提示。

**核对或重录旧点：**列表直接展示原始角度。「用当前位置重录」读取该点对应从臂的当前反馈，保留名称和步骤引用；核对角度后保存工作流。仅重命名不改变角度精度。手动改坐标会标记为手动输入。

旧点没有完整反馈时间戳时会显示提示，不能据此证明历史姿态准确。执行前会检查具体关节和限位；不会为了通过检查而修改旧点。录制值和合法命令范围是两回事，异常点应核对或重录。

当前从臂实测：`0x150` 的开始/结束示教记录指令能更新 `teach_status=1/2`，但开始记录后手推仍然锁住，不能据此宣称已开启零力拖动。因此仍使用机身按钮，不调用 leader 拖动接口、不切换为主臂，也不以失能释放替代重力补偿。

### 平滑回零与停止

平滑回零沿用采集模块的 SDK `move_j` 轨迹规划、30% 速度、1° 到位容差和连续三次反馈确认；直接作用于两只从臂，不创建采集模块的 `PiperPair`，也不使用主臂带动从臂。六个关节都回到 0°，不附加 J6 ±45° 预摆动作。回零完成或中断后恢复之前的速度设置。

默认保留夹爪宽度；需要采集模块那样同时闭合夹爪时，在「设备与恢复」勾选对应选项。回零支持「停止并保持」和急停；需要继续回零时再次点击即可。回零不修改任何已录制关键点或工作流步骤。

「双从臂急停」是 SDK 阻尼急停，不是回零，也不保证位置锁定。急停后先检查现场，再使用「从臂诊断与恢复」分别恢复左右从臂；不会自动复位。

### 从臂失能 / 急停恢复

连接 → **从臂诊断与恢复** → 选择左/右从臂 → 核对六轴角度、驱动码及恢复目标 → **恢复所选从臂**。诊断只读；恢复会在使能前预置当前附近的目标，必要时复位控制器急停，使能确认后再下发相同目标并验证反馈。采用 5% 速度，反馈略超软件限位时最多修正 3°；不回零、不操作夹爪、不改写编码器零点。急停复位时固件会短暂失能，须先托稳从臂并勾选确认；程序等待复位反馈稳定后重新使能。普通失能恢复不发送失能命令。恢复结果会显示在执行状态和弹窗内。

过流、堵转、通信异常、未退出示教或偏离限位超过 3° 时不执行恢复。`0x00` 失能不等于零位损坏；采集模块的主臂 J2 `0xA4` 标零流程不能直接照搬到从臂。确需标零时必须先核对物理零位。

### 旧版示教反馈异常的恢复

录点使用所选物理从臂的三组关节 CAN 反馈，要求六轴齐全、各组不超过 150 ms、组间差不超过 50 ms，并检查读取期间数据未被更新；不再仅相信 SDK 合并结果的最后一组时间戳。新点保存实际读取的原始弧度值、CAN 接口、三组接收时间和读取时间。读取、保存、预览都不发送运动指令。

若旧版留下错误的主从角色导致反馈缺失，可在「设备与恢复」点击「恢复从臂反馈」。此操作恢复从臂通信角色，不释放电机、不发送位置目标。正常录点无需此操作。

断开连接不会退出机身按键示教，也不会自动使能。需要恢复普通控制时，先用机身按钮退出示教。

### 管理与其他录点方式

共享关键点名称、共享模型名称各自在库内唯一；同一工作流的 VLA 步骤名称也唯一，名称首尾空白会去除。复制或重复添加会自动加编号，同一个点或模型仍可反复引用。手动重名会明确报错，JSON 导入和并发保存也执行同样检查。旧库重名升级时备份原库并加编号，保留 ID、坐标及引用；旧流程的重复 VLA 卡片名在打开时自动区分。

关键点支持命名、备注、修改、复制、删除、搜索、单点试运行和反复引用。列表直接展示全部共享点；新建工作流只清空编排，不清空点库或模型库。每次录点、编辑、重录立即保存到共享点库，所有工作流的引用共同更新；正在执行的流程保持启动时快照。「其他录点方式与坐标类型」支持刷新共享资源、手动输入或从 HDF5 提取。

关节输入使用角度，XYZ 和夹爪使用毫米，RPY 使用角度；文件和执行器统一使用弧度、米。位姿点的坐标系是各从臂自己的 base，目标是法兰。工作流启动时自动回零涉及双从臂；随后单臂点步骤只向对应从臂发送目标。列表中的「试运行」从当前位置执行该点，不先回零。


## 用深度相机选点

1. 连接设备，在设备配置中启用全局相机的对齐深度；相机使用采集模块的默认序列号，也可在本模块单独指定。
2. 在「相机选点」刷新预览，停止运动后「冻结画面以选点」。冻结时保存同一帧的 RGB、对齐深度，以及机械臂位姿。
3. 选择标定模块导出的 `calibration_bundle.json`。全局相机到左/右 base 使用 `global_left` / `global_right`；腕部使用对应的手眼外参，并与冻结时的法兰位姿相乘。
4. 点击目标表面，填写 TCP 相对法兰的 XYZ 偏移，以及 base 坐标中的接近偏移。默认沿 base Z 增加 50 mm；可按实际场景修改。
5. 保存关键点，在点库中试运行，查看机器人反馈误差并刷新相机观察工具落点。

选点保持冻结时的法兰朝向，用 TCP 偏移换算为法兰目标；不把物体表面误当作法兰位置。零深度、外参方向错误、相机身份或视频配置不匹配会明确报错。当前默认只有全局相机启用深度；仅有 RGB 的腕部不能直接由二维像素推算三维位置。

到位误差是机械臂反馈与目标的差值。它验证控制跟踪，不等同于独立测量外参或工具标定精度；实际落点需要配合画面或测量检查。

## 编排和执行

步骤支持：

| 步骤 | 配置与行为 |
| --- | --- |
| 关键点 | 选择已命名的点、期望运动时长、是否与下一个关节点衔接 |
| VLA | 选择模型、任务指令、控制侧别，按秒数、动作数或手动下一步结束 |
| 夹爪 | 选择左/右/双臂、宽度与动作时长 |
| 等待 | 等待指定秒数，也可以手动下一步 |

卡片可以拖动排序、上移、下移、复制和删除。支持从选中步骤开始、重复执行、暂停、继续、停止与双臂阻尼急停。运行使用启动时的工作流快照，运行期间编辑草稿只影响下次执行。

连续关节点使用五次多项式，共享中间点速度、保持结点加速度连续；停止点使用平滑起停。位置不经过任意样条外推，末端旋转沿 SO(3) 最短路径插值。期望时长不足以满足设置的速度和加速度时，执行器自动延长。末端点目前逐点平滑起停，不承诺不减速通过每个笛卡尔点，也不进行障碍物避让规划。

新建工作流默认参数：运控 50 Hz、关节速度 3 rad/s、关节加速度 3 rad/s²、末端线速度 1 m/s、末端角速度 0.5 rad/s、夹爪速度 1 m/s、VLA 进入衔接 0.6 s、提前准备下一 VLA 动作 1 s。新建关键点步骤的期望运动时长为 1 s。这些值来自操作者保存的「我的工作流」，不代表硬件极限；已保存流程及草稿保留各自参数。

每组运动结束后检查实际到位误差。没有到位会停止后续步骤并展示目标、实际反馈和误差，而不是按时间到了就假定动作成功。

## 多模型和提前准备

「VLA 模型」支持现有 LeRobot PyTorch 与 OpenPI JAX checkpoint，以及只供模拟器使用的模拟模型。每个模型单独设置名称、路径、动作模式、设备、policy Hz、默认指令和相机安装版本。

可以提前加载全部模型，也可以单独加载/卸载某个模型。开始工作流时，实际用到的模型自动在独立进程中加载、预热，与固定关键点执行并行。界面显示实际阶段：启动进程、加载权重、预热推理、就绪或失败，并保留日志。多个模型可以驻留在同一 GPU 或不同 GPU；同卡需要足够显存。

**选择 GPU：**在「VLA 模型」列表直接选择每个模型的推理设备，或在新增/编辑弹窗选择 → 点击该模型的「预加载」。批量加载按各模型保存的设备执行。GPU 区域显示物理编号、型号和已用/总显存，可手动刷新；右侧准备进度显示已加载实例的设备。改设备后只重新加载该模型，其他驻留模型保留；相同配置再次预加载复用现有进程。

PyTorch 和 OpenPI 均按物理 GPU 绑定独立进程，OpenPI 关闭启动时的大块显存预分配。同卡空闲模型主要占显存；后台加载、预热及提前推理会竞争算力。显存不足会展示错误，卸载不用的模型或换卡后可重试，不强制限制一张卡只能放一个模型。

进入 VLA 前会尝试提前推理首个动作 chunk。切换时若权重、预热或首个 chunk 尚未完成，机械臂保持目标并等待。控制切换从上一控制器的指令衔接，执行期间限制速度与加速度。加载预热与可控的平滑衔接已经实现，但模型耗时或显存不足时不能承诺零等待。

「VLA 进入衔接时间」是收到首个动作后，从上一控制目标逐渐过渡到 VLA 目标的时间，不是原地等待时长。「提前准备下一 VLA 动作」指当前步骤剩余时间进入该窗口、且紧接着是 VLA 步骤时，用当时的观测异步推理首个 chunk；它不控制模型权重加载，权重在工作流开始时已后台预加载。两者都不改变 policy Hz。

部署复用现有 `TargetSampler`，整段 chunk 在入队前解码为绝对目标，保留关节增量、绝对关节、绝对末端、腕部/全局相机增量位姿的原有语义。默认使用 guided RTC，取出动作的时机由各模型的 policy Hz 决定；不读取训练数据的采样 FPS，也不修改训练、转换或数据格式。

每张模型卡的「RTC 与运控高级参数」独立保存：

| 参数 | 含义 |
| --- | --- |
| policy Hz | 从动作队列取出一个目标的频率，与数据采集 FPS 无关 |
| control Hz | 该模型 VLA 步骤的控制下发频率；离开后恢复工作流运控频率 |
| 时间平滑常数 | 部署模块同款指数平滑，单位秒；0 关闭，与进入 VLA 的衔接时间独立 |
| 推理方式 | 异步 RTC 在队列尚有动作时补充下一 chunk；同步模式用完选定动作后再推理 |
| RTC 模式 | guided 或 trained；trained 需要支持训练时 RTC 的权重 |
| RTC horizon / queue threshold | 前缀覆盖步数 / 剩余多少动作时触发下一次推理 |
| OpenPI 采样步数 / 同步复用步数 | 去噪步数 / 每个同步 chunk 执行多少步；复用步数 0 表示跟随模型 |
| OpenPI schedule / 最大引导权重 / 屏蔽夹爪 | 与 OpenPI 部署页面的 RTC 参数含义相同 |

修改参数后再次预加载或执行，会按新配置加载模型；已开始的执行使用启动快照。RTC 复用部署模块的采样器与权重兼容性检查，trained 模式按推理耗时估算前缀延迟。

VLA 的结束条件由步骤定义。当前没有通过视觉自动判断任务完成的隐式逻辑；不确定任务耗时时，可选择手动「下一步」。

## VLA 模型操作

1. 打开顶层「VLA 模型」→ **新增模型**，填写名称、后端、checkpoint、动作模式和任务；RTC、policy Hz、control Hz、时间平滑常数在编辑弹窗内配置 → **保存模型配置**。
2. 模型列表可搜索、编辑/改名、复制配置、删除、预加载、卸载。点击 **添加步骤**可重复引用同一模型。
3. 编排页分别选择关键点或 VLA 模型再添加；**新模型**可直接新增并插入步骤，步骤内的 **编辑此模型**打开其实际引用的配置。
4. **保存模型配置**立即写入共享模型库，无需先保存工作流；**保存工作流**保存步骤、资源引用及运动参数。取消模型编辑不影响原配置，取消新增不会留下空模型。预加载与执行复用同一配置；未引用的旧模型草稿不阻塞执行，缺少 checkpoint 的实际使用模型会明确报出名称。

配置缺失时可点 **导入已加载模型配置**，恢复当前服务已加载的模型；不会覆盖已填写完整的配置。列表会区分“已就绪”和“配置已修改、需重新加载”。仅改名称/备注会复用权重；删除模型同时卸载它的进程。暂停、停止或结束执行时取消过期排队推理，正在运行的推理完成后丢弃结果；卸载模型不会阻塞状态查询。

回零/执行每次都会重新确认从臂六轴使能，避免机身示教改变状态后仍误用上次缓存。机身仍处于示教状态时，页面等待用户用按钮退出；不强行切换或释放电机。

## 保存与复现

全部资源统一保存在 `datasets/workflows/`：

| 文件 | 内容 |
| --- | --- |
| `point_library.json` | 所有工作流共享的命名关键点与坐标 |
| `model_library.json` | 所有工作流共享的 VLA 配置；权重保留原 checkpoint 路径 |
| `<工作流 ID>.json` | 工作流步骤、资源 ID 引用、运动与衔接参数 |
| `legacy_snapshots/` | 升级前旧工作流的完整备份 |

录点或保存模型后即可在任意工作流中使用，另一个页面也会同步。修改共享点或模型会影响所有引用它的工作流；想单独调整时先复制资源。删除需确认，会删除共享资源及所有已保存工作流中的相关步骤；删除某个编排卡片只删除当前步骤，共享资源配置保留；删掉当前流程最后一个 VLA 模型引用时，自动卸载该模型进程并释放显存。若正在执行，页面显示待卸载状态，本次执行结束/停止后再释放。删除共享模型则同时卸载其进程。已开始的执行使用固定快照。

旧工作流首次启动时自动迁移：已有共享点优先，模型从最近保存的旧工作流补入。浏览器旧草稿也会补入尚未入库的资源，已有共享配置不会被旧快照覆盖。磁盘写入使用跨进程锁，多个工作流服务共享同一目录。

支持工作流命名、保存、另存副本、JSON 导入/导出和浏览器草稿恢复。网页导出的 JSON 带资源完整配置，便于迁移；导入同 ID 资源时使用本机共享库的现有配置。

**采集起点兼容：**采集模块继续直接读取共享关键点，VLA 模型不会出现在起点候选中。采集起点独立保存在 `datasets/recorder/start_point.json`；共享点修改/删除不会改变已保存的采集起点，重新导入才采用新坐标。四臂返回起点及默认零位预摆逻辑不变。

「模拟示例」提供“基准点 → 模拟 VLA → 返回同一基准点”，可以完整验证界面和执行过程。模拟反馈不表示真实机械臂运动精度。
