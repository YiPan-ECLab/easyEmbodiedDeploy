## 0. 交付目标

本文只定义五种训练方法：

| 编号 | 方法 | 每臂模型动作 |
|---|---|---:|
| A | 绝对关节 J-ABS | 6 个绝对关节角 + 1 个绝对夹爪宽度 |
| B | 关节增量 J-ANCHOR | 相对 chunk 首帧的 6 个关节增量 + 1 个绝对夹爪宽度 |
| C | 绝对 EEF 位姿 EEF-ABS | base 下位置 3 + 绝对四元数 4 + 绝对夹爪宽度 1 |
| D | camera-based delta CAM-ANCHOR | 相对 chunk 首帧、用首帧相机轴表达的位移 3 + 旋转向量 3 +绝对夹爪宽度 1 |
| E | 上一帧 camera-based delta CAM-STEP | 相对上一帧、用上一帧相机轴表达的位移 3 + 旋转向量 3 +绝对夹爪宽度 1 |

系统关系固定为：

~~~text
EDA
  负责真机采集、同步数据生成、推理客户端、Piper 安全执行
        ↕
ce_openpi
  负责数据 transform、action chunk、归一化、PI0.5 训练和策略服务
~~~

## 1. 所有方法共用的定义

### 1.1 坐标系

- $B$：每只 Piper 自己的 base 坐标系；
- $E_t$：时刻 $t$ 的 EEF/TCP 坐标系；
- $C_t$：时刻 $t$ 选定的参考相机坐标系。

EEF 的绝对位姿为：

$$
{}^B T_{E,t}=
\begin{bmatrix}
{}^B R_{E,t} & {}^B p_{E,t}\\
0 & 1
\end{bmatrix}.
$$

${}^B R_{E,t}$ 是 $3\times3$ 旋转矩阵，${}^B p_{E,t}$ 是用 base 轴表示的三维位置。

参考相机在一个数据集版本内必须固定：

- 使用固定 head 相机时，标定并保存 ${}^B T_C$；
- 使用腕部相机时，标定并保存固定外参 ${}^E T_C$，每帧计算

$$
{}^B T_{C,t}={}^B T_{E,t}\,{}^E T_C.
$$

不得把第三人称相机坐标系和 Piper base 坐标系混称为同一个坐标系。

### 1.2 每个同步帧的母数据

每个 episode 最少采集：

| 字段 | 格式和含义 |
|---|---|
| image.head | head 相机 RGB |
| image.wrist | 本臂腕部相机 RGB；即使暂时不用，也建议保存 |
| follower_qpos | 6 维绝对关节角，rad |
| follower_gripper | 1 维绝对夹爪宽度，m |
| follower_eef_position | 3 维，Piper base 下绝对 TCP 位置，m |
| follower_eef_quaternion_wxyz | 4 维，Piper base 下绝对 TCP 朝向 |
| command_qpos、command_gripper | 能从 leader→follower 链路取得时记录真实下发命令 |
| 时间戳和序号 | 每条机器人反馈、命令、每台相机各自的单调时钟时间戳和序号 |
| 有效性 | 每路数据的 valid、丢帧和错误码 |
| episode 信息 | 任务文本、成功/失败、人工终止原因 |
| 标定信息 | 参考相机名、外参矩阵、标定版本和日期 |

五种方法的首轮公平比较统一使用 follower 实际轨迹作为监督目标。命令流用于分析遥操作延迟和跟踪误差，不在同一轮实验中混用为另一种监督来源。

当前 EDA 的 action=qpos.copy()，action_eef_pose=eef_pose.copy()；它们是同帧 follower 状态复制，不是真实控制命令，也不是已经构造好的未来 action。

### 1.3 同步和下一帧目标

先按机器人单调时间轴同步相机和机器人状态。图像必须在允许的最大时间误差内匹配；超限样本丢弃，不能静默复用过旧图像。

观测锚点为 $t$，采样周期为 $\Delta t$，chunk 长度为 $H$。统一定义：

$$
\tau_k=t+(k+1)\Delta t,\qquad k=0,\ldots,H-1.
$$

所以 chunk 第一项是下一帧，不是当前帧。

同步后的基础训练行应提供：

~~~text
observation.state[t]       = 当前 q[t] 和 g[t]
observation.eef_pose[t]    = 当前 base 下绝对 EEF pose
action_joint_absolute[t]   = 下一帧 q[t+1] 和 g[t+1]
action_eef_absolute[t]     = 下一帧 base 下 xyz、quaternion 和 g[t+1]
~~~

ce_openpi 在 anchor $t$ 读取连续的 $H$ 个绝对目标，得到 $\tau_0,\ldots,\tau_{H-1}$。不足 $H$ 个未来目标的 episode 尾部 anchor 直接排除，不跨 episode，也不复制最后一帧伪造运动。

### 1.4 四元数和旋转向量

原始绝对朝向统一保存为 quaternion_wxyz：

1. 每帧归一化为单位四元数；
2. episode 第一帧固定符号，例如优先令 $w\ge0$；
3. 后续帧若与上一帧点积小于 0，则整体乘 $-1$。

这一步消除 $q$ 与 $-q$ 的表示跳变。

camera delta 的旋转使用三维旋转向量：

$$
r_\Delta=\operatorname{Log}_{SO(3)}(R_\Delta).
$$

方向是旋转轴，模长是旋转弧度。它不是欧拉角；参与旋转乘法前必须通过 $\operatorname{Exp}_{SO(3)}$ 转成 $3\times3$ 旋转矩阵。

### 1.5 统一归一化

所有实验使用 ce_openpi 的 quantile normalization。必须先完成本方法的差分或几何预处理，再对最终送给模型的 state 和 actions 分维统计 $q_{01}$ 与 $q_{99}$：

$$
x_{\mathrm{norm}}
=2\frac{x-q_{01}}{q_{99}-q_{01}+10^{-6}}-1.
$$

推理反归一化：

$$
x
=\frac{x_{\mathrm{norm}}+1}{2}
(q_{99}-q_{01}+10^{-6})+q_{01}.
$$

注意：

- 每种 action 表示必须有独立的 dataset ID、asset ID 和 norm_stats.json；
- 不允许五种方法共用 action statistics；
- observation state 相同，但每个 checkpoint 仍携带自己的完整 stats；
- 归一化不会天然把异常值硬裁剪在 $[-1,1]$；
- delta 某一维几乎不运动时，应使用 ce_openpi 的 safe-quantile span guard，不能让 $q_{99}-q_{01}$ 接近零。

## 2. 方法 A：绝对关节 J-ABS

### 2.1 需要采集

- 当前 RGB 图像；
- 当前 follower $\mathbf q_t\in\mathbb R^6$ 和 $g_t$；
- 每个未来目标时刻的 follower $\mathbf q_{\tau_k}$ 和 $g_{\tau_k}$；
- 各流时间戳、任务文本和 episode 边界。

本方法不依赖 EEF pose 或相机外参，但母数据仍应统一采集它们，保证五种方法使用同一批 episode。

### 2.2 预处理

关节角统一为 rad，夹爪统一为 m。检查关节顺序、正方向和 Piper 实际限位。

每臂第 $k$ 个训练动作直接取未来绝对值：

$$
a_k^{J\text{-}ABS}
=
[q_{1,\tau_k},\ldots,q_{6,\tau_k},g_{\tau_k}].
$$

每臂 7 维，没有 pose 运算，没有相对锚点。

### 2.3 归一化

对最终 7 维 action 分别计算 quantile stats。关节和夹爪都按各自物理分布归一化。推理使用同一 checkpoint stats 反归一化。

### 2.4 chunk 组织

$$
A_t^{J\text{-}ABS}
=
\begin{bmatrix}
\mathbf q_{\tau_0} & g_{\tau_0}\\
\mathbf q_{\tau_1} & g_{\tau_1}\\
\vdots & \vdots\\
\mathbf q_{\tau_{H-1}} & g_{\tau_{H-1}}
\end{bmatrix}
\in\mathbb R^{H\times7}.
$$

每一行都是独立的绝对目标；后续行既不相对首帧，也不相对前一行。

### 2.5 ce_openpi 训练配置

~~~text
config_name: piper_pi05_j_abs
model observation state: q[t] + g[t]
action_sequence_key: action_joint_absolute
physical_action_dim_per_arm: 7
use_delta_joint_actions: false
input transform: 只做 Piper 字段和图像 repack，不做 DeltaActions
output transform: 保留反归一化后的 7 维绝对关节动作
normalization: quantile
~~~

训练数据加载器读取 action_joint_absolute[t:t+H]，直接形成 $H\times7$ actions。先运行该 config 的 norm-stats，再运行 PI0.5 训练。

### 2.6 推理解码

模型输出反归一化后已经是绝对 $[\mathbf q_{goal},g_{goal}]$。EDA 做关节限位、单步变化和夹爪范围检查后直接下发。

## 3. 方法 B：关节增量 J-ANCHOR

### 3.1 需要采集

- 当前 RGB 图像；
- 当前 follower $\mathbf q_t$ 和 $g_t$；
- 每个未来目标的绝对 $\mathbf q_{\tau_k}$ 和 $g_{\tau_k}$；
- 时间戳、任务文本和 episode 边界。

### 3.2 预处理

对一个 anchor $t$，chunk 中所有未来关节都减同一个 $\mathbf q_t$：

$$
a_k^{J\text{-}ANCHOR}
=
[\mathbf q_{\tau_k}-\mathbf q_t,\ g_{\tau_k}].
$$

只对 6 个关节做差；夹爪保持未来绝对宽度。

### 3.3 归一化

完成关节做差后，对最终 7 维动作计算本方法独立的 quantile stats。增量维通常以 0 为中心；夹爪仍按绝对宽度统计。

### 3.4 chunk 组织

$$
A_t^{J\text{-}ANCHOR}
=
\begin{bmatrix}
\mathbf q_{\tau_0}-\mathbf q_t & g_{\tau_0}\\
\mathbf q_{\tau_1}-\mathbf q_t & g_{\tau_1}\\
\vdots & \vdots\\
\mathbf q_{\tau_{H-1}}-\mathbf q_t & g_{\tau_{H-1}}
\end{bmatrix}.
$$

关键语义：每行都相对观测首帧 $\mathbf q_t$，不是 $\mathbf q_{\tau_k}-\mathbf q_{\tau_{k-1}}$。

### 3.5 ce_openpi 训练配置

~~~text
config_name: piper_pi05_j_anchor
model observation state: q[t] + g[t]
action_sequence_key: action_joint_absolute
physical_action_dim_per_arm: 7
use_delta_joint_actions: true
DeltaActions mask: [true, true, true, true, true, true, false]
AbsoluteActions mask: 与输入相同
normalization: quantile / safe_quantile
~~~

输入 transform 在归一化前执行 DeltaActions。输出 transform 在反归一化后执行 AbsoluteActions，对 chunk 中每一行加回同一个推理观测 $\mathbf q_t$。

### 3.6 推理解码

$$
\mathbf q_{goal,k}
=\mathbf q_t+\Delta\mathbf q_k.
$$

ce_openpi 可以完成这一步并向 EDA 返回绝对关节目标。EDA 不得再次加当前关节，否则会重复积分。

## 4. 方法 C：base 下绝对 EEF 位姿 EEF-ABS

### 4.1 需要采集

- RGB 图像；
- 当前 qpos 和夹爪，作为统一模型 observation state；
- 当前及每个未来时刻在 base 下的绝对 EEF 位置和四元数；
- 未来绝对夹爪宽度；
- Piper EEF/TCP 定义、工具偏移和物理单位；
- 时间戳、任务文本和 episode 边界。

本方法不依赖相机外参。

### 4.2 预处理

先执行第 1.4 节的 quaternion 归一化和符号连续化。每臂第 $k$ 行为：

$$
a_k^{EEF\text{-}ABS}
=
[{}^B p_{E,\tau_k},
{}^B q_{E,\tau_k}^{wxyz},
g_{\tau_k}].
$$

每臂 8 维。四元数是绝对旋转矩阵 ${}^B R_{E,\tau_k}$ 的参数化；需要几何运算时先转成 $3\times3$ 旋转矩阵。

### 4.3 归一化

对位置 3、四元数 4、夹爪 1 分维计算 quantile stats。推理反归一化后必须再次把四元数除以自身模长；必要时令其符号与当前 EEF quaternion 点积非负。

### 4.4 chunk 组织

$$
A_t^{EEF\text{-}ABS}
=
\begin{bmatrix}
{}^B p_{E,\tau_0} & {}^B q_{E,\tau_0}^{wxyz} & g_{\tau_0}\\
{}^B p_{E,\tau_1} & {}^B q_{E,\tau_1}^{wxyz} & g_{\tau_1}\\
\vdots & \vdots & \vdots\\
{}^B p_{E,\tau_{H-1}} & {}^B q_{E,\tau_{H-1}}^{wxyz} & g_{\tau_{H-1}}
\end{bmatrix}
\in\mathbb R^{H\times8}.
$$

所有行都是 base 下绝对目标，不依赖 chunk 锚点。

### 4.5 ce_openpi 训练配置

~~~text
config_name: piper_pi05_eef_abs
model observation state: q[t] + g[t]
geometry anchor field: observation.eef_pose[t]（部署和审计使用）
action_sequence_key: action_eef_absolute
physical_action_dim_per_arm: 8
use_delta_joint_actions: false
input transform: quaternion 清洗后 repack 为 xyz + quaternion_wxyz + gripper
output transform: 保留物理 8 维，不做 AbsoluteActions
normalization: quantile
~~~

该配置需要独立的 Piper EEF policy adapter，不能复用 7 维关节 mask。

### 4.6 推理解码

ce_openpi 返回反归一化后的绝对 EEF action。EDA：

1. 重新单位化 quaternion；
2. 构造 base 下绝对 ${}^B T_{E,goal,k}$；
3. 用 Piper 对应的 IK 求绝对关节目标；
4. 做 IK 可解性、关节限位和步长检查后执行。

## 5. 方法 D：chunk 首帧 camera-based delta CAM-ANCHOR

### 5.1 需要采集

- RGB 图像；
- 当前 qpos 和绝对夹爪；
- 当前及每个未来时刻在 base 下的绝对 EEF pose；
- 未来绝对夹爪宽度；
- 明确的参考相机名；
- 固定 head 相机的 ${}^B T_C$，或腕部相机的 ${}^E T_C$；
- 精确时间戳、任务文本和 episode 边界。

没有相机外参就不能构造该方法。外参错误会直接把 action 的平移轴和旋转轴变换错。

### 5.2 预处理

对 anchor $t$ 和每个未来目标 $\tau_k$，先在 base 轴下构造空间增量：

$$
{}^B\Delta p_k
={}^B p_{E,\tau_k}-{}^B p_{E,t},
$$

$$
{}^B R_{\Delta,k}
={}^B R_{E,\tau_k}({}^B R_{E,t})^\top.
$$

再把它们改用 anchor 相机 $C_t$ 的轴表达：

$$
{}^{C_t}\Delta p_k
=({}^B R_{C,t})^\top{}^B\Delta p_k,
$$

$$
{}^{C_t}R_{\Delta,k}
=({}^B R_{C,t})^\top
{}^B R_{\Delta,k}
{}^B R_{C,t},
$$

$$
{}^{C_t}r_{\Delta,k}
=\operatorname{Log}_{SO(3)}
({}^{C_t}R_{\Delta,k}).
$$

最终每臂动作：

$$
a_k^{CAM\text{-}ANCHOR}
=
[{}^{C_t}\Delta p_k,\ {}^{C_t}r_{\Delta,k},\ g_{\tau_k}].
$$

每臂 7 维。

### 5.3 归一化

必须先完成 base→camera 变换和 $SO(3)$ Log，再对最终 $[\Delta p_C,r_{\Delta,C},g]$ 计算独立 quantile stats。不能对绝对 pose 先归一化再做几何运算。

### 5.4 chunk 组织

$$
A_t^{CAM\text{-}ANCHOR}
=
\begin{bmatrix}
{}^{C_t}\Delta p_0 & {}^{C_t}r_{\Delta,0} & g_{\tau_0}\\
{}^{C_t}\Delta p_1 & {}^{C_t}r_{\Delta,1} & g_{\tau_1}\\
\vdots & \vdots & \vdots\\
{}^{C_t}\Delta p_{H-1} & {}^{C_t}r_{\Delta,H-1} & g_{\tau_{H-1}}
\end{bmatrix}
\in\mathbb R^{H\times7}.
$$

所有行都同时满足：

- EEF pose 锚点是同一个 ${}^B T_{E,t}$；
- 表达轴是同一个 ${}^B R_{C,t}$；
- 不是相邻行差分。

### 5.5 ce_openpi 训练配置

~~~text
config_name: piper_pi05_cam_anchor
model observation state: q[t] + g[t]
geometry anchor field: observation.eef_pose[t]
action_sequence_key: action_eef_absolute
camera calibration: dataset metadata 中固定 reference_camera 和 extrinsic
physical_action_dim_per_arm: 7
use_delta_joint_actions: false
input transform: 用 anchor EEF + H 个绝对未来 EEF 构造 CAM-ANCHOR chunk
output transform: 只反归一化，保留 camera delta
normalization: quantile / safe_quantile
~~~

几何 input transform 必须位于 normalization 之前；compute_norm_stats.py 统计的是最终 camera delta，不是原始 absolute EEF pose。

### 5.6 推理解码

对模型输出的每一行先执行 $SO(3)$ Exp：

$$
{}^{C_t}R_{\Delta,k}
=\operatorname{Exp}_{SO(3)}
({}^{C_t}r_{\Delta,k}).
$$

再用同一个推理首帧相机轴和 EEF pose 还原：

$$
{}^B\Delta p_k
={}^B R_{C,t}\,{}^{C_t}\Delta p_k,
$$

$$
{}^B R_{\Delta,k}
={}^B R_{C,t}\,
{}^{C_t}R_{\Delta,k}
({}^B R_{C,t})^\top,
$$

$$
{}^B p_{goal,k}
={}^B p_{E,t}+{}^B\Delta p_k,
$$

$$
{}^B R_{goal,k}
={}^B R_{\Delta,k}\,{}^B R_{E,t}.
$$

chunk 后续行也必须使用该次推理的首帧锚点。不能在执行中途改成当前实际 EEF，否则训练和部署语义不一致。

## 6. 方法 E：上一帧 camera-based delta CAM-STEP

### 6.1 需要采集

- RGB 图像；
- 当前 qpos 和绝对夹爪；
- 当前及每个未来时刻在 base 下的绝对 EEF pose；
- 未来绝对夹爪宽度；
- 参考相机名和对应外参；
- 精确时间戳、任务文本和 episode 边界。

### 6.2 预处理

定义每行的上一帧：

$$
\rho_0=t,\qquad
\rho_k=\tau_{k-1}\quad(k>0).
$$

第 $k$ 行从上一帧 $\rho_k$ 指向目标帧 $\tau_k$：

$$
{}^B\Delta p_k
={}^B p_{E,\tau_k}-{}^B p_{E,\rho_k},
$$

$$
{}^B R_{\Delta,k}
={}^B R_{E,\tau_k}
({}^B R_{E,\rho_k})^\top.
$$

使用上一帧相机轴表达：

$$
{}^{C_{\rho_k}}\Delta p_k
=({}^B R_{C,\rho_k})^\top{}^B\Delta p_k,
$$

$$
{}^{C_{\rho_k}}R_{\Delta,k}
=({}^B R_{C,\rho_k})^\top
{}^B R_{\Delta,k}
{}^B R_{C,\rho_k}.
$$

最终每臂动作：

$$
a_k^{CAM\text{-}STEP}
=
[{}^{C_{\rho_k}}\Delta p_k,\ 
\operatorname{Log}_{SO(3)}
({}^{C_{\rho_k}}R_{\Delta,k}),\
g_{\tau_k}].
$$

每臂 7 维。

### 6.3 归一化

完成相邻帧差分、相机轴变换和 $SO(3)$ Log 后，对最终 7 维 action 计算本方法独立的 quantile stats。CAM-STEP 的数值分布通常比 CAM-ANCHOR 更集中，绝对不能共享 stats。

### 6.4 chunk 组织

$$
A_t^{CAM\text{-}STEP}
=
\begin{bmatrix}
\Delta(T_t\rightarrow T_{\tau_0})\text{，用 }C_t\text{ 轴表达}\\
\Delta(T_{\tau_0}\rightarrow T_{\tau_1})\text{，用 }C_{\tau_0}\text{ 轴表达}\\
\vdots\\
\Delta(T_{\tau_{H-2}}\rightarrow T_{\tau_{H-1}})
\text{，用 }C_{\tau_{H-2}}\text{ 轴表达}
\end{bmatrix}.
$$

第一行相对观测帧；其余每行相对 chunk 中上一目标帧。这是唯一需要逐行递推才能恢复整条 EEF 目标轨迹的方法。

### 6.5 ce_openpi 训练配置

~~~text
config_name: piper_pi05_cam_step
model observation state: q[t] + g[t]
geometry anchor field: observation.eef_pose[t]
action_sequence_key: action_eef_absolute
camera calibration: dataset metadata 中固定 reference_camera 和 extrinsic
physical_action_dim_per_arm: 7
use_delta_joint_actions: false
input transform: 用 anchor EEF + H 个绝对未来 EEF 构造逐帧 CAM-STEP chunk
output transform: 只反归一化，保留逐帧 camera delta
normalization: quantile / safe_quantile
~~~

推荐让 transform 读取 anchor EEF 和完整的绝对未来 EEF sequence，再统一构造 chunk。也可以离线预先生成每行的单步 camera delta，然后让 LeRobot 顺序取 $H$ 行组成 chunk；此时必须保证第 $i$ 行严格表示 $i\rightarrow i+1$、保存对应参考相机定义，并且绝不跨 episode。两种实现产生的数值必须通过同一 round-trip 测试。

### 6.6 推理解码

从推理时当前实际 pose 开始：

$$
{}^B T_{prev}={}^B T_{E,t}.
$$

按 $k=0,\ldots,H-1$ 顺序：

1. 从 ${}^B T_{prev}$ 和相机外参求 ${}^B R_{C,prev}$；
2. 将模型的 camera 位移、旋转向量转换回 base 轴；
3. 计算

$$
{}^B p_{goal,k}
={}^B p_{prev}+{}^B\Delta p_k,
$$

$$
{}^B R_{goal,k}
={}^B R_{\Delta,k}\,{}^B R_{prev};
$$

4. 把本行 goal 更新成下一行的 $T_{prev}$；
5. 对每个绝对 EEF goal 做 IK 和安全检查。

这里必须逐行积分；不能像 CAM-ANCHOR 那样让所有行都加到最初 pose。

## 7. 五个训练脚本和配置的统一写法

后续 AI 不应编写五套训练器，而应共用 ce_openpi 训练入口，只新增五个 DataConfig/TrainConfig 和对应 action transform：

| config | 原始 action sequence | 几何或差分 transform | 每臂物理维数 |
|---|---|---|---:|
| piper_pi05_j_abs | absolute joint | 无 | 7 |
| piper_pi05_j_anchor | absolute joint | 首帧关节差分 | 7 |
| piper_pi05_eef_abs | absolute EEF | quaternion 清洗 | 8 |
| piper_pi05_cam_anchor | absolute EEF | 首帧 camera delta | 7 |
| piper_pi05_cam_step | absolute EEF | 上一帧 camera delta | 7 |

每种方法的标准训练流程：

~~~bash
# 1. 计算该 config 独立的 state/action quantile stats
uv run scripts/compute_norm_stats.py --config-name <config_name>

# 2. 用完全相同的 config 训练
XLA_PYTHON_CLIENT_MEM_FRACTION=0.9 uv run scripts/train.py <config_name> --exp-name=<experiment_name> --overwrite
~~~

训练配置必须把以下 metadata 写入 dataset、stats 和 checkpoint：

~~~text
robot_type: agilex_piper
action_semantics: 五种方法之一
action_dim_per_arm
active_arms 及拼接顺序
action_horizon
sample_period_seconds
target_offset_seconds = sample_period_seconds
reference_camera（仅 CAM 方法）
calibration_version（仅 CAM 方法）
dataset_id / asset_id
~~~

如果同时使用两只 Piper，就按固定左臂、右臂顺序拼接每臂 action；如果只训练一只，就只保留该臂，不允许用全零伪造不存在的另一只臂。PI0.5 内部多余 action 维可以补零，但 physical action dimension 和 loss mask 必须由 metadata 明确。

## 8. 推理端统一顺序

无论选择哪种方法，部署链路都是：

~~~text
EDA 采集当前图像、qpos、EEF pose
→ ce_openpi 按 checkpoint stats 归一化 observation
→ PI0.5 输出归一化 action chunk
→ ce_openpi 用同一 stats 反归一化
→ 按 action_semantics 解码
→ 得到绝对关节目标，或先得到绝对 EEF goal 再做 IK
→ EDA 做限位、步长、IK、夹爪、急停检查
→ Piper 接收绝对关节目标和绝对夹爪宽度
~~~

不允许根据 action 维数猜语义，因为 J-ABS、J-ANCHOR、CAM-ANCHOR 和 CAM-STEP 每臂都是 7 维。必须读取 checkpoint 的 action_semantics。

## 9. 交接验收

其他 AI 修改代码后必须提供以下测试：

1. 同步后的第一项目标确实是下一帧，不是同帧复制；
2. 五种 chunk 都不跨 episode；
3. J-ANCHOR 做差后再加 anchor 能恢复绝对关节目标；
4. EEF-ABS 反归一化并单位化 quaternion 后能恢复原绝对旋转；
5. CAM-ANCHOR 编码再解码能恢复每个 base 下绝对未来 pose；
6. CAM-STEP 逐行编码再积分能恢复整条 base 下绝对未来 pose；
7. 人工设置相机相对 base 旋转 $90^\circ$，camera delta 转回 base 后轴方向正确；
8. 每个 config 只加载自己的 norm_stats.json；
9. 训练、策略服务和 EDA 推理端读取到一致的 action_semantics；
10. 真机下发前所有路径都经过 Piper 关节限位、单步变化、夹爪范围和急停检查。

五组实验必须固定相同的 episode、图像、任务文本、划分、采样频率、chunk 长度、PI0.5 初始权重、训练步数和随机种子集合。主要比较任务成功率、安全停止次数、IK 失败率、EEF/关节跟踪误差和动作平滑度。
