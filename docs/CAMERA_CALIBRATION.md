# 相机标定使用说明

本模块完成相机内参、腕部手眼外参、全局相机对左右 base 的外参采样、求解、质量检查与导出。**尚未将位姿动作接入数据转换、训练或部署**；拟定链路见 [位姿动作数据流](POSE_ACTION_DATAFLOW.md)。

## 启动和文件位置

启动 `python3 workbench.py`，打开“相机标定”。也可单独运行：

```bash
thirdParty/.venvs/piper-home/bin/python scripts/CameraCalibration/web_server.py
```

标定记录位于 `datasets/calibration/<记录 ID>/`，包括：

| 文件 | 内容 |
| --- | --- |
| `session.json` | 板配置、相机身份、内参、角点、法兰位姿、时间戳、求解结果 |
| `<样本 ID>.png` | 原始 640×480 RGB 图像，无 224×224 缩放 |
| `<样本 ID>.jpg` | 带角点标号的核对图 |
| 导出目录的 `calibration_bundle.json` | 可复制路径或下载的标定包；记录缺少哪些外参 |

删除整个记录可到“模型与数据目录”模块，将对应目录移入回收站。不要在采样或求解期间移动当前记录。更改板配置须新建记录；既有记录加载自己保存的板参数。增删样本或更换内参会使原求解结果失效。

## 可自定义的标定板

默认棋盘格：**4 列 × 6 行内角点，单格 53.5 mm**。实际是 5×7 个格子，板面 267.5×374.5 mm。旋转板面后可将行列互换，但同一记录须保持同一物理坐标方向。

网页可修改板类型、列数、行数和格子尺寸。棋盘格的行列是**内角点数量**；ChArUco 的行列是**格子数量**，另可配置 ArUco 字典和标记占格子边长比例。不是把 4×6 写死在检测算法里。

网页可下载带真实毫米尺寸的 SVG。默认棋盘连同四周 10 mm 白边可放入 A3。打印选择 **100% / 实际大小**，不要“适应纸张”，打印后量尺检查格子尺寸。安装在平整、刚性的背板上。更大板面应选择相应纸张。

普通棋盘格有 180° 方向歧义，内角点检测不能自动保证物理原点相同。请在板外给固定内角点做标记，使用“检测角点”查看标号 **0**；必要时将“棋盘角点顺序旋转”设为 180°；自定义方形棋盘还支持 90° / 270° 重排。每次样本都要让 0 对应同一物理内角点。ChArUco 通过编码识别角点，不使用棋盘重排选项。

## 三台相机，四项外参

约定 `T_A_B` 把 B 坐标变换到 A：`p_A = T_A_B @ p_B`，平移统一用米。

| 网页任务 | 求解结果 | 标定板如何固定 |
| --- | --- | --- |
| 左腕 | `T_left_flange_left_camera` | 板固定在环境中，左腕相机跟随左臂运动 |
| 右腕 | `T_right_flange_right_camera` | 板固定在环境中，右腕相机跟随右臂运动 |
| 全局 → 左 base | `T_left_base_global_camera` | 板刚性固定到左法兰，随左臂运动；全局相机不动 |
| 全局 → 右 base | `T_right_base_global_camera` | 板刚性固定到右法兰，随右臂运动；全局相机不动 |

“相机 → 左法兰”明确表示 **$^{F_L}T_{C_L}$**，既不是 $^{B_L}T_{C_L}$，也不是 $^{C_L}T_{B_L}$。它把左腕相机中的点变到左法兰坐标：`p_F_L = T_F_L_C_L @ p_C_L`。结合当前 SDK 反馈的法兰位姿才得到 `T_B_L_C_L = T_B_L_F_L @ T_F_L_C_L`。

“全局相机 → 左 base”才是 **$^{B_L}T_{C_G}$**。如果需要相反方向，取该矩阵的逆。右侧同理。

左右机械臂有各自的 base。全局相机必须分别求出相对两个 base 的变换。不能把左 base 的结果直接用在右臂上。完成全局的两份记录期间，相机和两个 base 都应保持同一安装状态。

**腕部和全局的板固定方法不同。** 全局任务不能照搬“板固定在桌上、机械臂运动”的采样方法，这样相机图像不包含与法兰相关的运动，不能解出要求的关系。

“安装版本”由操作者填写，例如 `table-2026-09-v1`。同一安装版本可合并四项外参；移动相机安装位置、相机支架或机械臂 base 后应换版本并重做受影响的标定。软件能检查版本和设备身份，无法自动证明实物从未移动。

## 网页采样流程

1. 选择四项外参之一，或选择“相机内参重标定”。相机序列号可编辑，默认沿用采集脚本的角色映射。
2. 点击“打开相机”。默认只读对应**从臂**的法兰位姿；内参任务无需机械臂。可以取消只读连接，采样时手动填入该帧的 `xyz(m), roll/pitch/yaw(rad)`。
3. 配置板参数、记录名称、安装版本，然后新建记录。SDK 内参自动随相机视频配置保存。
4. 根据上述固定方式，使用你已有的方式改变机械臂或标定板姿态。标定页面不负责移动机械臂，也不启动示教、使能、回零或模式切换。与采集和部署共用设备锁，不能同时占用这些服务的设备。
5. 每个姿态静止后检测角点，检查原点；确认“机械臂与标定板已静止”，保存样本。棋盘需完整可见，ChArUco 需至少 8 个可见内角点。
6. 至少采 8 个样本，建议 15–25 个。外参需要绕两个以上不同方向变化的旋转；仅平移或单轴旋转不能可靠求解。内参还需要板面在画面四周、中心以及不同倾角出现。
7. 求解并检查每张图的重投影误差，以及静态关系的平移 / 旋转残差。可查看、移除问题样本并重新求解。
8. 勾选已求解记录，导出 JSON 标定包或复制其路径。部分结果允许导出，但文件会列出缺少的任务。有质量提示时，须检查后显式接受，才能导出。
9. 完成后关闭相机，释放设备供采集或部署使用。仅切换工作台页面不会关闭相机。

采样保存相机接收时的 monotonic 时间、主机采样墙钟时间和 SDK 位姿时间。它们不是同一时钟，也没有硬件触发同步；因此本流程要求**静止采样**。这些时间戳只记录来源，不通过新增控制逻辑干预原采集器。

## 求解、质量和 SDK 对照

SDK 阅读依据：

- `thirdParty/pyorbbecsdk/examples/beginner/04_camera_calibration.py`：内参、畸变和深度到 RGB 的设备内部外参；内部外参平移单位为 mm。
- `thirdParty/pyorbbecsdk/src/pyorbbecsdk/stream_profile.cpp`：`VideoStreamProfile.get_intrinsic()` / `get_distortion()`。
- `thirdParty/pyorbbecsdk/src/pyorbbecsdk/types.cpp`：畸变模型和参数顺序。
- `scripts/PiperRecorder/piper_recorder/camera.py`：相机角色、左右彩色传感器优先选择及普通 RGB 回退；新模块复用这一实现，不改动采集器。
- `thirdParty/pyAgxArm/pyAgxArm/protocols/can_protocol/drivers/piper/default/driver.py:get_flange_pose`：xyz 为 m，RPY 为 rad，固定轴 XYZ，`R=Rz(yaw) Ry(pitch) Rx(roll)`。
- SDK 的 `ArmDriverAbstract.connect()` 只建立通信和启动接收线程；新模块只调用 `connect/get_flange_pose/disconnect`，不初始化夹爪、不设置机械臂模式、不发送运动。

新模块取得**实际选中的视频 profile** 的内参。不能用另一个 RGB / 左右传感器的内参代替。Orbbec 深度→RGB 外参也不能代替相机→机器人外参。

畸变映射：Brown 使用 `[k1,k2,p1,p2,k3]`，Brown K6 使用 `[k1,k2,p1,p2,k3,k4,k5,k6]`；无畸变使用零向量；Kannala–Brandt4 走 OpenCV fisheye 路径。未明确兼容的 Modified / Inverse Brown 模型不会被当成普通 Brown 使用，需重标定内参。

**默认直接使用出厂内参，不需要先做内参重标定。** 打开相机即读取所选 RGB profile 的 K、D，新建记录时写入 `session.json → camera.intrinsics`；导出时写入 `calibration_bundle.json → calibrations[].camera.intrinsics`。来源字段为 `orbbec_selected_video_profile`。

网页“当前使用的内参”显示来源、记录 / 设备身份、分辨率、K 与 D，求解前即可查看。选择历史记录时显示该记录保存的内参，不会用另一台已打开相机的参数替换它。尚未新建记录时，显示当前相机的出厂值。

原先“应用内参”的下拉框只列**手工重标定**记录，所以没有记录并不表示缺少出厂内参。现在此入口位于“高级：改用手工重标定内参”，只列当前记录同序列号、传感器及分辨率的已求解结果。没有匹配记录时按钮禁用，正常出厂内参流程不受影响。每张图保存角点，因此更换内参后可以重新做 PnP。

外参使用 [OpenCV `calibrateHandEye`](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html) 的 PARK 方法：

- 腕部输入 `T_base_flange`、PnP 的 `T_camera_board`，得到 `T_flange_camera`；检查 `T_base_flange @ T_flange_camera @ T_camera_board` 是否恒定。
- 全局输入 `inverse(T_base_flange)`、`T_camera_board`，得到 `T_base_camera`；检查 `inverse(T_base_flange) @ T_base_camera @ T_camera_board` 是否恒定。

重投影误差是像素 RMS。外参残差是上述静态关系相对全部样本平均位置 / 平均旋转的 RMS；**它是拟合一致性，不能代替独立测量的绝对精度**。当前以 2 px 单帧重投影、5 mm 平移 RMS、2° 旋转 RMS 作为提示线，不声称这是硬件精度保证。内参还提示覆盖范围和倾角不足。

真实精度验收应使用未参加求解的新姿态、独立测量点或已知尺寸，检查工作范围内的误差。视野受限、板面弯曲、错误原点、机械间隙、运动模糊都可能影响结果。

## 与后续位姿链路的衔接

| 后续动作模式 | 标定操作 | 转换与训练中的用途 |
| --- | --- | --- |
| 左右各自 base 下绝对位姿 | 不需要标定 | 直接使用从臂反馈位姿生成未来目标 |
| 各自腕部 camera delta | 先左腕、再右腕，各自求解后勾选导出 | 结合当前法兰位姿，把未来相对运动变到各自当前腕相机方向 |
| 全局 camera delta | 先全局→左 base，再全局→右 base，使用同一固定相机安装 | 分别用两份外参把左右相对运动变到全局相机方向 |

每份记录完成后关闭相机，再切换任务打开下一份。三台相机、四项外参全部需要时，顺序可为**左腕 → 右腕 → 全局左 base → 全局右 base → 合并导出**；同一安装版本下的全局两项之间不能移动相机或 base。

本轮按最新要求**暂停位姿转换、训练和部署扩展**。导出包可保存和复制路径，目前不能在现有关节转换 / 训练器中选择使用；后续接入方案见 [简化后的位姿链路](POSE_ACTION_DATAFLOW.md)。

## 本轮可复现验收

- 自动回归：`python3 tests/run_checks.py`，包含已知真值的腕部 / 全局方向、内参、退化运动拒绝、自定义棋盘 / ChArUco 检测和导出失效机制。
- 三台真实相机已分别验证 RGB 图像和对应 profile 内参读取；左右从臂均已验证只读法兰位姿读取，未发送运动指令。
- 实物板面未在当前视野中，尚未取得真实手眼外参。现场只需核对三项：板参数与实际尺寸一致；按四项任务各采一组样本；用新姿态验收导出外参的精度。
