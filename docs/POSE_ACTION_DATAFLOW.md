# 位姿动作链路（方案说明，暂不实现）

本轮按要求暂停位姿功能扩展。数据转换、训练和部署仍使用现有**关节动作链路**；标定模块独立保存、求解和导出结果。本文只明确后续位姿链路，不增加输入维度或模型结构设计。

## 1. 输入数据与输出动作

原始 HDF5 中，`obs/left_ee_states`、`obs/right_ee_states` 是左右**从臂实测法兰位姿**：

```text
[x, y, z, roll, pitch, yaw]，单位 m / rad，各自在自己的 base 下
```

现有 `actions` 是主臂关节与夹爪命令，并不是位姿标签。后续位姿方案用**从臂未来实测位姿**作目标；夹爪沿用对应未来帧的绝对宽度命令。采集器、脚踏板流程和原有关节模式不变。

每只手的最终预测动作都是：

```text
[位置 3 维, 旋转向量 3 维, 夹爪宽度 1 维]
双臂合计 14 维 action
```

这里的旋转向量是轴角 `rotvec`，不是欧拉角 RPY。

## 2. 两种动作模式

| 模式 | 位置标签 | 旋转标签 | 需要的标定 |
| --- | --- | --- | --- |
| `absolute_base_pose` | 未来法兰在该手自身 base 下的绝对 xyz | 未来绝对旋转矩阵对应的 3D rotvec | **不需要相机标定** |
| `camera_delta_pose / own_wrist` | 相对当前帧的位移，分别在当前左右腕相机中表达 | 同一相机系下的相对旋转 rotvec | 左、右腕相机到各自法兰的外参 |
| `camera_delta_pose / global` | 相对当前帧的位移，左右手都在全局相机方向中表达 | 同一相机系下的相对旋转 rotvec | 全局相机到左、右 base 的两份外参 |

绝对模式不把左右 base 合并成世界坐标系，也不因缺少标定包而阻止转换、训练或部署。

## 3. 旋转和 camera delta 的计算

约定 `T_A_B` 将 B 坐标变到 A，`p_A = T_A_B @ p_B`。B 为该手自身 base，F 为法兰，C 为所选相机。

SDK 的固定轴 XYZ 欧拉角先转换为矩阵：

```text
R_B_F = Rz(yaw) @ Ry(pitch) @ Rx(roll)
```

camera delta 采用 [Qwen-RobotManip §3.3 公式 (5)](https://arxiv.org/html/2606.17846v1#S3.S3)。当前观测时刻为 t，未来目标为 t+k：

```text
delta_p_C = R_B_C(t).T @ (p_B_F(t+k) - p_B_F(t))
delta_R_C = R_B_C(t).T @ R_B_F(t+k) @ R_B_F(t).T @ R_B_C(t)
```

腕部视角：`T_B_C(t) = T_B_F(t) @ T_F_C`。全局视角：各手使用自己的 `T_B_C` 标定结果。**整个未来动作 chunk 都冻结在观测时刻 t 的相机方向下**，不跟随未来腕部姿态重新定义参考系。

旋转处理链为：

```text
原始 RPY → 旋转矩阵 → 绝对 / 相对目标旋转
→ 6D 表示（矩阵前两列按列拼接）→ 还原旋转矩阵 → 3D rotvec 训练标签
```

6D 顺序固定为 `[R00,R10,R20,R01,R11,R21]`，还原采用 Gram–Schmidt 正交化；6D 是几何处理中间表示，**最终动作旋转仍为 3 维**。不直接相减欧拉角，也不使用会耦合相机平移偏置的公式 (6)。

Qwen §3.2 的**观测 state** 使用 6D 姿态，**预测 action** 使用 3D 相对旋转向量；这是两件事。本文不把 Qwen 完整的 80 维跨机器人模板移植到 PI05，也不要求 32 维 state。位姿模型的观测字段和维度留到恢复实现时单独确定。

## 4. 从采集到训练、部署

```text
原始 HDF5
  → 选择 task 段、排除 home，按目标 FPS 统一选帧
  → 当前帧图像 / 观测 + 未来 t+1…t+H 法兰目标
  → 按绝对 base 或 camera delta 生成 14 维动作 chunk
  → 仅用有效目标计算位姿专用统计量
  → LeRobot / OpenPI 训练、保存动作语义与标定信息
  → 模型预测 14 维位姿动作
  → 解码为左右自身 base 下的绝对法兰目标
  → 转为执行接口要求的表示，再由单独验证的位姿执行分支执行
```

转换时先选帧，再算相对动作。不得跨 episode、task/home 或异常时间缺口取未来目标。首个目标为 `t+1`，不是当前帧自身；尾部不足 H 步可以重复末帧，但需 mask 排除填充位置的训练损失和统计量。

camera delta 解码：

```text
p_B_F* = p_B_F(t) + R_B_C(t) @ delta_p_C
R_B_F* = R_B_C(t) @ delta_R_C @ R_B_C(t).T @ R_B_F(t)
```

chunk 中每步都相对同一锚点还原，不能逐步累加。RTC 跨锚点复用动作时，先还原 base 绝对目标，再按新锚点重编码。位姿动作虽也是 14 维，**不能送入现有关节目标接口**。

数据集、训练配置和 checkpoint 须记录动作模式、参考相机、坐标系、单位、rotvec 约定、未来目标偏移、mask 规则及对应统计量。camera delta 另保存标定包、安装版本和相机身份，并确认与采集时安装一致。

## 5. 标定如何衔接

- **绝对 base**：跳过标定，直接使用原始从臂位姿生成标签。
- **腕部 camera delta**：完成左右腕两份外参，导出同一安装版本的标定包。
- **全局 camera delta**：完成全局相机对左右 base 的两份外参，导出同一安装版本的标定包。
- 默认直接使用选中 RGB 视频配置的**出厂内参**做角点 PnP；无需先做内参重标定。内参帮助求外参，不直接进入上述 delta 公式。
- 后续转换器选择该标定包，训练器读取数据契约，部署按同一动作语义解码。**这些接入本轮均未实现。**

具体板固定方式、网页操作顺序和矩阵方向见 [相机标定使用说明](CAMERA_CALIBRATION.md)。恢复实现后需验证旋转回环、公式方向、冻结锚点、时间边界、mask、统计量、两套训练器及小步真机执行；不能用合成标定结果冒充真实安装外参。
