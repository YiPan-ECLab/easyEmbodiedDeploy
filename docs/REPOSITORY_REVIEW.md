## 不变的核心契约

- Piper 30 Hz 默认采样，200 Hz 跟随；J6 左 -45°、右 +45°。
- 操作流程：初始回零 → 指令/回车沿用 → 预定位 → 真人动作触发记录 → 回车结束 → 回零仍采样 → 回车保存/n 丢弃 → 下一轮。
- HDF5：14 维未归一化 rad/m；task 前缀、home 后缀；时间空档拒绝保存。
- 转换：task 选择及尾部裁剪 → 固定网格降采样 → 可选 `action[t+1]-action[t]`。
- LeRobot/OpenPI 各自使用原训练入口、归一化、checkpoint 和 RTC 算法。
- 部署：delta 累加/absolute 直通 → 限位 → 绝对目标低通 → 现有硬件控制线程。
- 打开 Web、发现服务和查看状态不触发设备运动。

| 部署退出 | 12 秒强制结束可能截断最长 60 秒回零；加载失败可能遗留桥；重复停止可打断已有回零 | 等待部署/桥各自清理；识别正在回零的桥；模型退出自动清理本页桥；回零超时保留现场并记录错误 |
| 部署参数 | LeRobot 未核对显式训练动作语义；trained RTC 边界未在页面提前校验；CLI 接受部分 NaN | 启动前核对 manifest 和 RTC 范围；有限值校验；无 manifest 的旧模型仍保留显式人工选择 |
| 部署功能 | LeRobot dry-run、OpenPI 离线数据入口未完整呈现在页面 | 添加对应控件，严格映射原 CLI；离线启动不创建硬件桥 |

| 训练生命周期 | 验证期间取消仍可能启动训练；停止状态会被日志覆盖；退出后计时继续 | 取消代次、退出锁、稳定状态、结束时间；回收日志管道和子进程 |
| 训练元数据 | LeRobot 只在成功结束后写训练清单，中间 checkpoint 缺动作契约 | 输出目录由原训练器创建后就记录 running 清单；完成后更新清单 |
| 训练恢复/发现 | 恢复数据动作语义未完整核对；OpenPI 扫描复制来的旧机器绝对路径导致整个 bootstrap 500 | 恢复前核对显式动作语义；发现列表从本机 manifest 所在目录枚举 checkpoint |

| 浏览器/API | 大/负长度请求、跨站 POST、掉线、代理资源路径及百分号文件名边界 | 共用有界 JSON reader、同源控制检查、连接断开处理、有限数值序列化；修正双重 URL 解码 |

### 真机记录与现场验收

已经完成：

- 三路相机均有非空 224×224 RGB 图像。
- 双从臂回零、J6 −45° / +45° 预定位。
- 基于初始位置的两侧 J1 +0.005 rad 小幅目标和返回初始目标；实际控制 30 次，测得 30.0005 Hz，最大观测单周期关节变化约 0.001641 rad。
- NaN 和越限目标被拒绝；RPC stop 后双从臂与夹爪完成回零。后续模型 dry-run 也在退出时完成双从臂回零。
- 采集首次四臂与夹爪回零成功；预定位出现主臂通信问题，错误没有继续进入记录或保存。

首次测试的历史异常：第一次采集预定位左侧超时；复测右主臂反馈停在 0°，右从臂已到 +44.98°，随后同步回零恢复失败。当时系统读取到 `piper-rt` 为 **ERROR-PASSIVE**，夹爪示教器无响应；之后右主臂仅收到 CAN 错误帧，左主臂没有有效反馈。当时两个主臂最终位置无法确认。**后续 A/B 复测已确认新增反馈判定存在软件回归；完整恢复原版后，四臂及夹爪均由原版流程确认回零。** 历史 CAN 错误的具体诱因未确定，不再据此断定硬件故障。

仍需真人完成的两项采集验收：

1. 在工作台进入 Piper 采集，实际踩踏板完成一条短示教：指令 → J6 预定位 → 示教 → 踩停 → 回零 → 踩保存；再做一次丢弃，确认操作习惯、页面焦点和真实踏板回车与预期一致。
2. 用轨迹浏览核对刚才的文件：三路画面对齐、task/home 分段正确；再运行转换/分析，确认这条真实人工示教可用于训练。完整任务部署效果需要你在场评估，未用模型输出驱动大幅运动。
