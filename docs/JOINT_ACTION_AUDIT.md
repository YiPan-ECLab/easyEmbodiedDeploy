# 绝对关节与相对关节链路排查

结论：发现了会影响相对关节的部署及训练问题，不能把现有效果差异全部归因于“绝对关节天生更好”。修复并不保证相对关节在本任务上最终胜出；还需用相同数据、训练步数和多次任务成功率作对照。

## 已确认并修复

| 问题 | 原行为 | 当前行为 |
| --- | --- | --- |
| RTC 丢失增量位移 | 推理期间过期的步骤先从 chunk 删除，再只累计剩余增量 | 以推理观测关联的上一指令为锚点，先累计完整 chunk 为绝对目标，再裁剪排队；新推理的 RTC 前缀重新变成逐步增量 |
| 尾部重复增量进入 loss | 数据加载补齐 chunk 时重复 episode 最后一个 action；最后增量非零时，会监督模型继续运动 | 两套相对关节训练均排除 episode 尾部填充；trained RTC 同时排除已知前缀，并为尾部样本保留有效监督 |
| OpenPI 内部补维混入新分支 loss | 原始网络动作维度含 32 维 padding | 新相对关节 / 位姿训练只监督真实的 14 个动作轴，保留原网络参数形状与采样接口 |

第一项可用确定性轨迹复现：每步 0.01 rad，推理丢弃前三步；旧流程的首个目标为 0.01 rad，正确首个目标应为 0.04 rad。测试同时覆盖新 RTC 前缀反编码，保证后续重规划不重复累计。

原始关节标签保持不变：`absolute_joint` 是当前选帧的主臂绝对命令；`delta_joint` 是降采样后 `command[t+1] - command[t]`，夹爪也取差分。state 均为当前从臂关节 / 夹爪反馈。没有把历史 delta 模型改解释成“相对当前 state 的全部未来目标”。

旧相对关节检查点可使用新的完整 chunk 部署还原，但**训练尾部掩码修复只对重新训练生效**。已有检查点已经学到的行为不会因部署端更新自动消失。

## 当前真实数据中的差异

对 `datasets/hdf5/撕下快递单并贴到桌子上的快递上` 的 61 条录制，以现有关节选帧 / 裁尾规则降至 10 Hz，共 7,346 个选中帧做了只读统计：

| 指标 | episode 间中位数 |
| --- | ---: |
| 关节增量绝对值小于 1e-5 rad 的比例 | 57.7% |
| 最后一个关节增量的 L2 范数 | 0.00675 rad |
| 50 步 chunk 的旧尾部重复填充占比 | 21.5% |
| 第一帧主臂命令与从臂反馈关节 L2 差 | 0.0315 rad |
| 命令 / 反馈 RMSE 最低的正向位移匹配 | 1 个 10 Hz 采样步 |

最后一项只是在 0…10 步候选位移中的描述性匹配，不是硬件延迟的精确测量。它说明命令与反馈有可见错位：delta 标签相对的是主臂命令，而部署初次锚点只能从从臂反馈建立，可能留下起始偏差。绝对关节每次直接给目标，较少受这类累积锚点偏差影响。

增量零值较多、非零动作稀疏，以及累计小偏差造成漂移，也是合理的效果影响因素。它们不能单凭离线统计归因，更不能只比较两种训练 loss 的数值：目标分布、归一化和监督含义并不相同。

## 如何做公平的效果对照

使用同一组 episode、选帧频率、任务文本、state、训练 / 验证划分、初始模型、训练步数和随机种子。先分别检查转换误差与 checkpoint 归一化；再固定推理方式、控制频率和 RTC 延迟设置，比较任务成功率、终点偏差、轨迹漂移与运行期断粮。

本轮的单步 GPU 训练、模型加载、同步 / RTC 推理以及有界真机测试用于证明链路可执行和几何 / 时序正确，**不等同于长时间任务训练效果评测**。不以单步新模型驱动大范围真实动作。
