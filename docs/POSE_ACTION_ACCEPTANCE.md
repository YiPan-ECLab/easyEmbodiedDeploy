## 测试发现后修复的实际问题

- RTC 过期裁剪前未累计完整关节增量，会丢失位移；新队列先解码完整段为绝对目标，并冻结与观测对应的指令锚点和前缀。
- 相对关节尾部补齐重复最后增量，原训练会监督继续运动；新训练排除填充，RTC 已知前缀也排除，两套后端逐样本对有效目标求平均。
- 位姿 DataLoader 的局部类无法在 spawn worker 中序列化，已改为模块顶层类。
- PyTorch guided RTC 需要对 noisy action 局部求导，已使用允许局部 enable_grad 的 no_grad 上下文。
- OpenPI 把仅含编号 0 的有效检查点视作空目录，已在项目入口修复；空目录恢复会明确报错。恢复产生的新检查点也会补齐可迁移的动作契约。
- J2=J3=0 位于 SDK 笛卡尔 IK 的限位边缘，数值舍入可能导致目标被拒绝。新增明确可配置的位姿起始关节偏移，默认 J2=+2°、J3=−2°；关节部署流程不变。首次失败及后续修复后的运动均计入本轮检查，没有把拒绝执行算作通过。
- 转换页刷新后曾使用当前表单给旧结果标注动作模式，已改为结果本身的模式与 FPS；质量分析的位姿提示显示 WARN，并增加关节标签诊断摘要。

相对关节的真实数据统计和原因边界见 [关节动作排查](JOINT_ACTION_AUDIT.md)。

## 验收范围与使用顺序

模拟外参验证的是矩阵方向、数据和代码衔接。真实标定精度、完整人工示教，以及模型训练收敛后的物理任务成功率没有被上述短测证明。未用单步新模型输出驱动无边界真实动作；模型真机图像推理采用 dry-run，实际运动使用已知、有界目标。

使用顺序为 **标定（camera delta 才需要）→ 采集 → 转换 → 分析 → 训练 → dry-run → 短步部署**。具体板固定方式、出厂内参、四项外参和网页参数见 [相机标定说明](CAMERA_CALIBRATION.md)；14D state/action 和 t+1…t+50 公式见 [位姿链路](POSE_ACTION_DATAFLOW.md)。

你后续只需完成：

1. 按真实安装状态完成所需的左右腕 / 全局双 base 标定，使用未参与求解的新姿态验证精度。
2. 用实际示教数据充分训练，再验收任务成功率；比较关节绝对 / 相对时保持数据和训练条件一致。
3. 按原脚踏板习惯实际采集一条，再在统一网页走完所选模式。

自动复现入口：`python3 tests/run_checks.py`。浏览器入口为 `tests/browser_smoke.py`、`tests/browser_theme.py`、`tests/browser_resources.py`，均支持 `--url` 指向自行启动的工作台；资源测试会清理自己创建的记录。GPU 与硬件测试应使用已安装环境、实际数据和明确小步参数。

测试临时数据、单步权重、截图与日志在交付前清理；保留可复现测试代码及本验收记录。用户原始数据、模型、标定记录和已有工作台不作为测试产物删除。
